# 脈絡新生隊｜中醫數位四診輔助 × PPG × FHIR 健康資訊系統

- **隊伍名稱：** 脈絡新生隊
- **作品名稱：** 中醫數位四診輔助 × PPG × FHIR 健康資訊系統
- **主題領域：** 醫療資訊／問卷與資料收集應用
- **使用者角色：** 病人／醫護人員／系統管理員
- **核心 FHIR Resources：** `Patient`、`Practitioner`、`Questionnaire`、`QuestionnaireResponse`、`Observation`、`Device`、`ClinicalImpression`
- **Demo 入口：**
  - 本機網址：`http://127.0.0.1:5000/`
  - 操作方式：執行 `START.bat` 後，系統會自動啟動後端並開啟瀏覽器。
  - Demo 影片：(https://youtu.be/8weQo4fh5HI)
- **Demo 測試帳號：**
  - 病人：`C000000003`
  - 醫護人員：`B000000002`
  - 系統管理員：`A000000001`
  - 預設密碼：`Test1234!`
  - 以上皆為競賽用虛構測試帳號，不含真實個人資料。
- **如何執行：** 
  1. 從 GitHub 下載專案壓縮檔，解壓縮後進入專案資料夾。
  2. 使用 Windows 電腦雙擊 `START.bat`。

  4. 瀏覽器會自動開啟 `http://127.0.0.1:5000/`。

  6. 關閉背景伺服器時，執行 `STOP_SERVER.bat`。

## 作品簡介

本作品整合中醫九大體質問卷、聞診資料與 PPG 生理量測，讓病人能在同一系統完成問卷與健康資料紀錄；醫護人員可依病人身分證字號搜尋病人，查看問卷、心率、血氧、HRV、聞診、歷史紀錄與原始錄音，並新增、修改或刪除專業評估；系統管理員則負責帳號、角色、密碼重設、系統設定與 Audit log。

健康資料會轉換為 FHIR R4 Resource，並可同步至 HAPI FHIR Server，再由 Server 讀回驗證。病人端不提供 FHIR 上傳按鈕，病人只需完成健康評估並儲存；FHIR 同步由系統後端自動處理，預設每 60 分鐘嘗試一次。醫護端仍保留手動同步／讀回功能，方便必要時重試與競賽 Demo。

本作品另外加入 Patient 假名化識別、PPG 裝置／手動輸入混合機制、聲音錄製分析、健康評估歷史管理、HAPI 重複資源處理，以及三角色權限控制，使本作品不只展示 FHIR JSON，而是一套可實際操作的健康資料整合原型。

## 主要功能

### 病人端

- 病人註冊與登入
- 中醫九大體質 45 題問卷
- 問卷採 1～5 數字量級顯示
- 問卷分頁、進度條與漏答提示
- 聞診聲音錄製與氣味自述資料
- 聲音分析包含錄音長度、平均音量 dBFS、基本頻率估計 Hz
- PPG 心率、SpO₂、HRV
- 支援 PPG 裝置偵測與自動讀取
- 支援 Device／Manual／Mixed 資料來源
- 查看個人健康紀錄與醫護評估
- 短時間重複儲存時更新同一次評估，避免產生重複歷史
- 病人端不提供 FHIR 上傳按鈕，FHIR 同步由後端處理

### 醫護端

- 以病人身分證字號搜尋病人
- 新增病人
- 查看問卷、PPG、聞診與歷史資料
- 查看九大體質分數
- 查看 45 題問卷回答的 1～5 數字量級
- 直接播放病人原始錄音
- 新增 `ClinicalImpression`
- 修改或刪除自己建立的醫護專業註記
- 修改／刪除註記時需再次輸入目前醫護帳號密碼確認
- 依本機病人身分自動查詢對應 FHIR pseudonym 與 HAPI Patient
- 執行 HAPI FHIR 建立／更新／讀回
- 保留手動同步功能，方便必要時重試與競賽展示

### 管理員端

- 系統人員主檔
- 登入帳號與 FHIR／病歷主檔分開顯示
- 帳號搜尋、建立與刪除
- 密碼重設
- 重要操作再次驗證管理員密碼
- Demo／正式身分證驗證模式
- Audit log
- 操作紀錄固定高度可滾動顯示
- 健康評估刷新時間設定，預設 5 分鐘
- FHIR 自動同步開關
- FHIR 自動同步間隔設定，預設 60 分鐘
- 查看最近同步成功時間與失敗訊息
- 可手動立即觸發一次同步

## FHIR 資料對應

| 系統資料 | FHIR Resource |
|---|---|
| 病人醫療身分 | `Patient` |
| 醫護人員 | `Practitioner` |
| 九大體質問卷 | `Questionnaire` |
| 問卷回答 | `QuestionnaireResponse` |
| 心率、SpO₂、HRV、體質分數、聲音分析 | `Observation` |
| PPG 感測器／麥克風 | `Device` |
| 體質摘要與醫護評估 | `ClinicalImpression` |

### 體質資料表示方式

本系統不將「氣虛質、陽虛質等體質傾向」表示為疾病 `Condition`。

```text
QuestionnaireResponse
→ 保存病人 45 題實際回答

Observation
→ 保存九大體質分數

ClinicalImpression
→ 保存體質摘要與醫護專業評估
```

## PPG 資料來源

系統支援三種 PPG 資料來源：

- **Device**：由 PPG 裝置直接取得資料。
- **Manual**：未偵測到裝置時，由使用者手動輸入。
- **Mixed**：部分數值由裝置取得，其餘數值由使用者手動補充。

系統會保留各筆量測的實際資料來源，不會為了補齊欄位而自行推算不存在的數值。

目前硬體方向：

```text
Arduino Nano 33 IoT
+
MAX30101
+
MAX32664
```

PPG 在本作品中定位為**切診輔助量化資料**，不等同完整中醫脈診。

## 聞診聲音資料

病人可透過瀏覽器麥克風錄製聲音，系統會分析：

- 錄音長度
- 平均音量 dBFS
- 基本頻率估計 Hz

分析結果轉換為 `Observation`。

原始錄音檔保留於本機系統，供病人及有權限的醫護人員播放與判讀；原始音訊檔本身不視為 `Observation` 數值。

若錄音過短、音量過低或無法取得有效基本頻率，系統會顯示無法估算，不產生假數值。

---

## 聞診氣味資料

目前未使用電子鼻，因此氣味資料採病人主觀自述方式蒐集，相關資料保存於 `QuestionnaireResponse`。

> 氣味資料為使用者主觀填寫，不是感測器直接量測。

## HAPI FHIR Server 資料交換

病人儲存健康評估後，系統會在本機保留資料並標記同步狀態。後端自動同步工作預設每 **60 分鐘**執行一次，僅處理尚未同步或本機已有更新的資料。

```text
病人儲存健康評估
      ↓
本機建立／更新 Assessment
      ↓
標記為待同步／已更新
      ↓
Background FHIR Sync Worker
（預設每 60 分鐘）
      ↓
轉換為 FHIR Resource
      ↓
檢查是否已有遠端對應 Resource
      ↓
┌────────────────┬────────────────┐
│ 尚未建立       │ 已經存在       │
↓                ↓
POST 建立        PUT 更新／沿用
└────────┬───────┘
         ↓
保存／沿用 HAPI Resource ID
         ↓
GET Resource/{id}
         ↓
讀回並驗證
         ↓
更新同步狀態與最後同步時間
```

### 自動同步原則

- 病人不需也不能主動執行 FHIR 上傳。
- 後端自動同步失敗不影響病人本機資料儲存。
- 失敗資料保留待下次自動同步或由醫護／管理員手動重試。
- 自動同步不會建立新的 Assessment 歷史，只同步既有資料。
- 管理員可啟用／停用自動同步，並調整同步間隔。
- 預設同步間隔為 60 分鐘。
- 自動同步成功與失敗會記錄於 Audit log／同步狀態。

### Resource 建立與更新

主檔型 Resource，例如 `Patient`、`Practitioner`、`Device`、`Questionnaire`、`Organization`，採建立／更新／沿用方式，避免重複上傳造成 HTTP 412 duplicate resource。

不同時間真正完成的新評估仍會形成新的歷史型資料，例如 `QuestionnaireResponse`、`Observation`、`ClinicalImpression`、`Encounter`、`DiagnosticReport`。

## 病人 FHIR 假名化識別

病人在本機以身分證字號作為登入帳號與醫護搜尋依據，但 HAPI FHIR Server 不直接使用身分證字號作為 Patient identifier。

每位病人會建立固定 pseudonym，例如：

```text
FHIRP-8F5E41041FA647D19EF3DD1394297E08
```

```text
身分證帳號
    ↓
本機 Patient
    ↓
FHIR pseudonym
    ↓
HAPI FHIR Server
```

從 HAPI 讀回 Patient 時，再由本機 mapping 將 pseudonym 對回原本病人。

此機制屬於**假名化（pseudonymization）**，不是完全匿名化，因為本機仍保存 pseudonym 與病人的對照關係。

## 健康評估歷史紀錄

為避免短時間重複儲存造成大量重複健康紀錄，系統加入「評估刷新視窗」機制。

預設刷新時間為 **5 分鐘**，可由管理員調整。

- 同一病人在刷新時間內再次儲存：更新同一次 Assessment，不新增重複歷史。
- 超過刷新時間再次完成評估：建立新的 Assessment，保留為新的歷史紀錄。
- 問卷、PPG、聲音分析與原始錄音均套用同一套邏輯。

> **短時間重複操作視為刷新，隔一段時間重新評估則保留為真正的健康歷史。**

---

## 醫護專業註記管理

醫護人員可新增、修改或刪除自己建立的專業註記。

- 修改與刪除均需再次輸入目前醫護帳號密碼。
- 不允許修改或刪除其他醫護建立的註記。
- 修改與刪除操作會寫入 Audit log。
- 刪除前會再次顯示該筆註記內容與時間。

---

## 帳號與資料安全

- 病人以身分證字號作為本機登入帳號。
- 密碼僅保存不可逆 `password_hash`。
- 暫時密碼只在建立或重設成功當下顯示一次。
- 刪除登入帳號不會自動刪除對應病歷／FHIR 主檔。
- 管理員頁將「登入帳號」與「FHIR／病歷主檔」分開顯示。
- 敏感操作需再次輸入目前登入者密碼確認。

## 注意事項

- 本作品為 FHIR 競賽與教學實作系統，並非正式臨床診斷系統。
- PPG 為切診輔助量化資料，不等同完整中醫脈診。
- 聞診聲音分析屬於輔助紀錄，不作為獨立疾病診斷依據。
- 聞診氣味目前為使用者自述資料，不是電子鼻量測。
- 九大體質結果為問卷評估結果，不等同正式疾病診斷。
- 公開測試型 HAPI FHIR Server 僅應使用虛構測試資料。
- 正式部署仍需使用 Private HAPI FHIR Server、HTTPS、完整權限控制、備份與資安管理。
- 正式系統規劃與 FHIR 詳細設計請參考專案中的 `系統規劃文件.md`。
