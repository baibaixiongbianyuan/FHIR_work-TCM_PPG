- **隊伍名稱：** 脈絡新生隊

## 作品簡介

本作品整合中醫九大體質問卷、聞診資料與 PPG 生理量測，讓病人能在同一系統完成問卷與健康資料紀錄；醫護人員可依病人身分證字號搜尋病人，查看問卷、心率、血氧、HRV、聞診、歷史紀錄與原始錄音，並新增、修改或刪除專業評估；系統管理員則負責帳號、角色、密碼重設、系統設定與 Audit log。

健康資料會轉換為 FHIR R4 Resource，並可上傳至 HAPI FHIR Server，再由 Server 讀回驗證。系統另外加入 Patient 假名化識別、PPG 裝置／手動輸入混合機制、聲音錄製分析、健康評估歷史管理、HAPI 重複資源處理，以及三角色權限控制，使本作品不只展示 FHIR JSON，而是一套可實際操作的健康資料整合原型。

## 主要功能

### 病人端

- 病人註冊與登入
- 中醫九大體質 45 題問卷
- 問卷採 1～5 數字量級顯示
- 問卷分頁、進度條與漏答提示
- 聞診聲音錄製與氣味自述資料
- 聲音分析包含錄音長度、平均音量 dBFS、基本頻率估計 Hz
- PPG 心率、SpO₂、HRV
- 支援 PPG 裝置偵測與自動讀取
- 支援 Device／Manual／Mixed 資料來源
- 查看個人健康紀錄與醫護評估
- 短時間重複儲存時更新同一次評估，避免產生重複歷史

### 醫護端

- 以病人身分證字號搜尋病人
- 新增病人
- 查看問卷、PPG、聞診與歷史資料
- 查看九大體質分數
- 查看 45 題問卷回答的 1～5 數字量級
- 直接播放病人原始錄音
- 新增 `ClinicalImpression`
- 修改或刪除自己建立的醫護專業註記
- 修改／刪除註記時需再次輸入目前醫護帳號密碼確認
- 依本機病人身分自動查詢對應 FHIR pseudonym 與 HAPI Patient
- 執行 HAPI FHIR 建立／更新／讀回

### 管理員端

- 系統人員主檔
- 帳號搜尋、建立與刪除
- 密碼重設
- 重要操作再次驗證管理員密碼
- Demo／正式身分證驗證模式
- Audit log
- 操作紀錄固定高度可滾動顯示
- 健康評估刷新時間設定
- 預設刷新時間為 5 分鐘，可由管理員調整

## FHIR 資料對應

| 系統資料 | FHIR Resource |
|---|---|
| 病人醫療身分 | `Patient` |
| 醫護人員 | `Practitioner` |
| 九大體質問卷 | `Questionnaire` |
| 問卷回答 | `QuestionnaireResponse` |
| 心率、SpO₂、HRV、體質分數、聲音分析 | `Observation` |
| PPG 感測器／麥克風 | `Device` |
| 體質摘要與醫護評估 | `ClinicalImpression` |

### 體質資料表示方式

本系統不將「氣虛質、陽虛質等體質傾向」表示為疾病 `Condition`。

目前採用：

```text
QuestionnaireResponse
→ 保存病人 45 題實際回答

Observation
→ 保存九大體質分數

ClinicalImpression
→ 保存體質摘要與醫護專業評估
```

如此可避免將體質傾向誤表示為正式疾病診斷。

## PPG 資料來源

系統支援三種 PPG 資料來源：

### Device

當系統偵測到可用 PPG 裝置時，可直接讀取裝置提供的數值。

### Manual

若未偵測到裝置，使用者仍可手動輸入心率、SpO₂ 與 HRV。

### Mixed

若裝置只能提供部分數值，例如只取得心率與 SpO₂，HRV 可由使用者手動補充。

系統會保留各筆量測的實際資料來源，不會為了補齊欄位而自行推算不存在的數值。

目前硬體方向：

```text
Arduino Nano 33 IoT
+
MAX30101
+
MAX32664
```

PPG 在本作品中定位為**切診輔助量化資料**，不等同完整中醫脈診。

## 聞診聲音資料

病人可透過瀏覽器麥克風錄製聲音，系統會分析：

- 錄音長度
- 平均音量 dBFS
- 基本頻率估計 Hz

分析結果轉換為 `Observation`。

原始錄音檔則保留於系統中，供病人及有權限的醫護人員播放與判讀；原始音訊檔本身不視為 `Observation` 數值。

若錄音過短、音量過低或無法取得有效基本頻率，系統會直接顯示無法估算，不會產生假數值。

---

## 聞診氣味資料

目前未使用電子鼻，因此氣味資料採病人主觀自述方式蒐集，例如：

- 口氣
- 汗液氣味
- 痰液氣味
- 排泄物氣味
- 其他異常體味

相關資料保存於 `QuestionnaireResponse`。

> 氣味資料為使用者主觀填寫，不是感測器直接量測。

## HAPI FHIR Server 資料交換

系統不再每次都直接對所有 Resource 重複 `POST`，而是依 Resource 類型判斷是否已存在遠端對應資料。

實作流程：

```text
本機健康資料
      ↓
轉換為 FHIR Resource
      ↓
檢查是否已有遠端對應 Resource
      ↓
┌────────────────┬────────────────┐
│ 尚未建立       │ 已經存在       │
↓                ↓
POST 建立        PUT 更新／沿用
└────────┬───────┘
         ↓
保存／沿用 HAPI Resource ID
         ↓
GET Resource/{id}
         ↓
讀回並驗證
```

主檔型 Resource，例如 `Patient`、`Practitioner`、`Device`、`Questionnaire`、`Organization`，採建立／更新／沿用方式，避免重複上傳造成 HAPI HTTP 412 duplicate resource 錯誤。

而不同時間真正完成的新評估，仍會保留新的歷史型資料，例如：

- `QuestionnaireResponse`
- `Observation`
- `ClinicalImpression`
- `Encounter`
- `DiagnosticReport`

## 病人 FHIR 假名化識別

病人在本機以身分證字號作為登入帳號與醫護搜尋依據，例如：

```text
R123456789
```

但對外上傳至 HAPI FHIR Server 時，系統不直接使用身分證字號作為 FHIR Patient identifier。

每位病人會建立固定的假名化識別碼，例如：

```text
FHIRP-8F5E41041FA647D19EF3DD1394297E08
```

本機保存：

```text
身分證帳號
    ↓
本機 Patient
    ↓
FHIR pseudonym
```

HAPI FHIR Server 端只使用 pseudonym。

從 HAPI 讀回 Patient 時：

```text
HAPI Patient
    ↓
取得 pseudonym
    ↓
查詢本機 mapping
    ↓
對回原本 Patient
    ↓
醫護端顯示本機病人資料
```

此機制屬於**假名化（pseudonymization）**，不是完全匿名化，因為本機仍保存 pseudonym 與病人的對照關係。

## 健康評估歷史紀錄

為避免使用者短時間內重複按下儲存或同步，造成大量重複健康紀錄，系統加入「評估刷新視窗」機制。

預設刷新時間為 **5 分鐘**，且可由管理員調整。

### 5 分鐘內再次儲存

同一病人在刷新時間內再次儲存：

- 視為同一次健康評估更新
- 更新本次問卷、生理量測、聲音與相關評估資料
- 錄音也更新同一次 Assessment 對應的錄音
- 不另外產生一筆重複歷史
- HAPI 已存在的對應 Resource 會更新或沿用

### 超過刷新時間再次儲存

超過設定時間後再次完成評估：

- 視為新的健康評估
- 建立新的歷史紀錄
- 保留新的問卷、PPG、聞診與相關資料
- 建立新的歷史錄音紀錄

因此系統同時兼顧：

> **短時間重複操作不產生假歷史，長時間後重新評估仍完整保留健康資料歷史。**

## 醫護專業註記管理

醫護人員可針對病人建立專業評估註記。

自己建立的歷史註記可：

- 修改
- 刪除

修改或刪除時，系統會要求目前登入的醫護人員再次輸入自己的密碼確認。

此外：

- 不允許醫護人員修改或刪除其他醫護建立的註記
- 修改與刪除操作會寫入 Audit log
- 刪除前會再次顯示該筆註記內容與時間，避免誤刪

## 帳號與權限

### 病人

- 以身分證字號作為本機登入帳號
- 只能查看自己的健康資料
- 可自行註冊

### 醫護人員

- 可搜尋與查看病人健康資料
- 可新增病人
- 可建立醫護評估
- 可執行 HAPI FHIR 資料交換

### 系統管理員

- 可管理系統人員主檔
- 可重設病人密碼
- 可管理身分證驗證模式
- 可調整健康評估刷新時間
- 可查看 Audit log

密碼只保存不可逆 `password_hash`，系統不保存可直接查看的原始密碼。

## 注意事項

- 本作品為 FHIR 競賽與教學實作系統，並非正式臨床診斷系統。
- PPG 為切診輔助量化資料，不等同完整中醫脈診。
- 聞診聲音分析屬於輔助紀錄，不作為獨立疾病診斷依據。
- 聞診氣味目前為使用者自述資料，不是電子鼻量測。
- 九大體質結果為問卷評估結果，不等同正式疾病診斷。
- 公開測試型 HAPI FHIR Server 僅應使用虛構測試資料。
- 正式部署仍需使用 Private HAPI FHIR Server、HTTPS、完整權限控制、備份與資安管理。
- 正式系統規劃與 FHIR 詳細設計請參考專案中的「系統規劃文件」。
