## 作品簡介

本作品以「病人健康資料」為核心，把中醫四診概念、PPG 生理量測、健康歷史、醫護評估及 FHIR 資料交換整合在同一套三角色系統中。

病人完成健康評估後先儲存在本機，不需要操作 FHIR 上傳；後端預設每 60 分鐘自動同步核心 FHIR 資料。醫護可以查閱每次 Assessment、播放錄音、建立專業註記與必要時手動同步；管理員負責帳號、權限、同步與系統設定。

預約／排班為本機便利功能，完全使用 SQLite，不建立 `Schedule / Slot / Appointment` FHIR Resource，也不送到 HAPI。

# 中醫四診在系統中的定義

這是本作品最重要的功能對應：

| 四診 | 系統中的資料／功能 | FHIR 對應 |
|---|---|---|
| **望** | **決賽預定新增**：病人拍照／上傳舌象、面色等影像供醫護判讀。目前尚未建立影像資料。 | 目前不產生 FHIR |
| **聞** | 聲音錄製與分析＋氣味主觀自述 | 聲音分析 → `Observation`；麥克風 → `Device`；氣味回答 → `QuestionnaireResponse` |
| **問** | 中醫九大體質 45 題問卷 | 題目 → `Questionnaire`；回答 → `QuestionnaireResponse`；九大體質分數 → `Observation` |
| **切** | PPG 心率 HR、SpO₂、HRV，作為切診**輔助量化資料** | 數值 → `Observation`；感測器 → `Device` |

> PPG 不等同完整中醫脈診；氣味目前不是電子鼻量測；望診影像尚未在初賽版實作。

醫護對體質結果的摘要、專業判讀與健康建議，例如「建議多喝水」，使用 `ClinicalImpression`。

# 主要功能

## 病人端

- 三角色登入頁中的病人登入／註冊。
- 九大體質 45 題問卷：1～5 數字量級、5 頁分頁、進度條、漏答提示。
- 下一次評估自動帶入上一次 45 題回答，有變化再修改，也可清空重填。
- 聞診聲音錄製：錄音長度、平均音量 dBFS、基本頻率 Hz 等輔助特徵。
- 氣味資料採病人主觀自述。
- PPG：HR、SpO₂、HRV。
- 支援 Device／Manual／Mixed 資料來源，不自行補造不存在的量測值。
- 查看以 Assessment 分組的完整健康歷史與醫護評估。
- 選醫護＋可預約開始時間建立本機預約。
- 預約完成後立即顯示醫護、日期、開始～預估結束、預估分鐘數與狀態。
- 預約建立後 10 分鐘內可自行取消。
- 病人端沒有 HAPI 上傳按鈕。

## 醫護端

- 以身分證字號搜尋病人。
- Assessment 健康歷史採卷軸式顯示。
- 每次 Assessment 點「查看完整紀錄」才展開 HR／SpO₂／HRV、九大體質分數、45 題回答、氣味、聲音、原始錄音與醫護註記；歷史下方不再重複顯示同一批資料。
- 可播放病人原始錄音。
- 可新增多筆醫護專業註記並綁定 Assessment。
- 自己建立的註記可修改／刪除，需再次輸入密碼。
- 註記的新增、修改、刪除另保留本機版本歷史；目前有效內容使用 `ClinicalImpression`。
- 保留手動 HAPI 同步與讀回，供 Demo／重試。
- 本機排班可建立「時間段 → 多日期」，再建立其他時間段與日期。
- 同一天時間段若重疊，先提醒，確認後合併成連續區間。
- 醫護日程直接顯示病人姓名與預約開始～結束時間。
- 可設定每位病人的個別建議看診時長。
- 可記錄實際開始／實際結束；提早完成會釋放剩餘空檔，不會自動提前下一位病人。

## 管理員端

- 登入帳號與 FHIR／病歷主檔分開管理。
- 帳號建立、搜尋、刪除與密碼重設。
- Demo／正式身分證驗證模式。
- Audit log。
- Assessment 刷新時間設定，預設 5 分鐘。
- FHIR 自動同步開關與同步間隔，預設 60 分鐘。
- 查看最近同步成功／錯誤狀態並可立即同步。
- 全系統預約基礎排程單位由管理員調整，預設 5 分鐘；新排班套用新設定，既有排班不重切。
- 重要設定修改需重新輸入管理員密碼。

# Assessment 健康歷史

一次 Assessment 是本機的一次完整健康評估分組，可包含問、聞、切資料與醫護註記。

預設刷新視窗為 **5 分鐘**：

```text
5 分鐘內再次儲存
→ 更新同一次 Assessment
→ 不建立重複歷史

超過刷新視窗重新完成評估
→ 建立新的 Assessment
→ 保留新的不同時間健康歷史
```

FHIR 時間欄位會保留實際評估時間，例如：
- `Observation.effectiveDateTime`
- `QuestionnaireResponse.authored`
- `ClinicalImpression.date`

# FHIR 資料範圍

目前 HAPI 只同步 7 種核心 Resource：

| 系統資料 | FHIR Resource |
|---|---|
| 病人健康資料主體 | `Patient` |
| 醫護專業身分 | `Practitioner` |
| 九大體質／氣味題目 | `Questionnaire` |
| 45 題回答／氣味自述 | `QuestionnaireResponse` |
| HR、SpO₂、HRV、體質分數、聲音分析 | `Observation` |
| PPG、麥克風來源 | `Device` |
| 體質摘要、醫護判讀與建議 | `ClinicalImpression` |

**不送 HAPI：** `Person`、`Organization`、`Encounter`、`DiagnosticReport`、`Schedule`、`Slot`、`Appointment`、排班預約、個別看診時長、實際看診時間、原始錄音、登入帳號、密碼、角色與 Audit log。

# HAPI FHIR 同步

## 後端自動同步

- 預設每 60 分鐘執行。
- 只處理待同步／有更新的核心 FHIR 資料。
- 同步失敗不影響本機健康資料儲存。
- 醫護／管理員可必要時手動同步及 GET 讀回驗證。

## 防止重複上傳

同一筆本機 Resource：

```text
第一次 → POST 建立
再次同步 → PUT 更新原本那一筆
```

因此重按同步不會一直增加相同資料。

真正不同時間的新 Assessment 才會建立新的歷史 FHIR Resource。

## 公用 HAPI 最近 10 次 Assessment

完整歷史保留在本機 SQLite；公用 HAPI 為避免累積大量競賽測試資料，**每位病人只維持最近 10 次 Assessment 的歷史型展示資料**。

主要適用：
- `Observation`
- `QuestionnaireResponse`
- `ClinicalImpression`

第 11 次之後循環重用最舊的遠端展示槽；本機第 1 次到最新一次全部保留。

# Patient 假名化

本機使用身分證帳號登入與搜尋，但公用 HAPI 不直接送原始身分證。

```text
本機 Patient
→ 固定 FHIR pseudonym（FHIRP-...）
→ HAPI Patient
```

讀回後以本機 mapping 對回原病人。此機制為 **pseudonymization（假名化）**，不是完全匿名化。

# 本機預約／排班（非 FHIR）

排班及預約完全使用 SQLite：

- 時間段綁定多個日期。
- 可再建立其他時間段與其他日期。
- 同日重疊時段先提醒，確認後合併。
- 管理員設定基礎排程單位，預設 5 分鐘。
- 醫護可設定一般預估時長及病人個別建議時長。
- 病人只選醫護與開始時間，結束時間由系統自動計算。
- 後端再次檢查連續空檔，避免不同病人撞期。
- 病人與醫護於預約建立後 10 分鐘內可取消。
- 醫護可記錄實際開始／結束；提早結束後依基礎排程單位釋放剩餘時間。

> 排班、預約及實際看診時間皆**不進 FHIR、不上傳 HAPI**。

# 資料安全

- 密碼僅保存 `password_hash`。
- 暫時密碼只在建立／重設時顯示一次。
- 登入帳號與病歷／FHIR 主檔分離，刪帳號不等於刪病歷。
- 敏感操作需再次輸入目前登入者密碼。
- 公用 HAPI 僅使用虛構測試資料。

# 注意事項

- 本作品為 FHIR 競賽與教學原型，不是正式臨床診斷系統。
- **望診：決賽預定以照片／影像上傳供醫護判讀，目前未正式實作。**
- **聞診：聲音分析＋氣味自述。**
- **問診：中醫九大體質 45 題。**
- **切診：PPG HR／SpO₂／HRV，只作輔助量化，不等同完整脈診。**
- 正式部署需使用 Private HAPI FHIR、HTTPS、完整權限管理、備份與資安機制。

詳細流程與資料規劃請參考 `系統規劃文件.md`。
